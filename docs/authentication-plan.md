# Регистрация и авторизация в бэкенде

## Итог

Создать Go API с регистрацией по email, логину и паролю. Для входа запрашивать два поля: email или логин и пароль. Использовать access JWT и refresh-токен в HttpOnly cookie. Для работы с PostgreSQL выбрать GORM с драйвером `gorm.io/driver/postgres`.

## Реализация

- Добавить HTTP-сервер, конфигурацию через переменные окружения и модели GORM для пользователей и refresh-сессий. PostgreSQL запускать через `backend/docker-compose.yml`, API — отдельно. Создавать схему через `AutoMigrate`, а уникальность email и логина закрепить индексами в БД.
- Реализовать `POST /api/v1/auth/register` с полями `email`, `login`, `password`. Пароль хранить как bcrypt-хеш. При успешной регистрации сразу выдавать access JWT и устанавливать refresh cookie.
- Реализовать `POST /api/v1/auth/login` с полями `identifier` и `password`. `identifier` принимает email или логин без учёта регистра. Проверять пароль по хешу; при успехе выдавать access JWT и устанавливать refresh cookie.
- Реализовать `POST /api/v1/auth/refresh`: хранить в БД только хеш refresh-токена и атомарно заменять токен в транзакции GORM с блокировкой строки. Повторное использование старого токена отклонять.
- Реализовать `POST /api/v1/auth/logout` для отзыва текущей refresh-сессии и удаления cookie, а также `GET /api/v1/users/me` для проверки access JWT.
- Разрешить запросы с credentials только с настроенного origin фронтенда, по умолчанию `http://localhost:3000`. Вынести в окружение ключ подписи, сроки токенов и настройку `Secure` для cookie. Документировать запуск и запросы API.

## Проверка

Покрыть тестами регистрацию и конфликты идентификаторов, вход по email и логину с паролем, неверный пароль, доступ к `/me`, ротацию и повторное использование refresh-токена, выход. При параллельных запросах обновления успешным должен быть только один. Выполнить `gofmt`, `go test ./...`, `go build ./...` и проверить конфигурацию Compose.

## Принятые условия

Регистрация сразу создаёт сессию. Подтверждение email и восстановление пароля не входят в эту версию. Access JWT действует 15 минут, refresh-токен — 30 дней; выход отзывает refresh-сессию, а уже выданный access JWT действует до истечения срока.
