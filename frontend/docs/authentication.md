# Фронтенд авторизации

Запустите PostgreSQL и API по инструкции `backend/docs/authentication.md`. Затем из каталога `frontend/`:

```sh
npm install
npm run dev
```

Для одновременного запуска API и фронтенда можно использовать `./scripts/dev.sh` из корня проекта. Сначала запустите PostgreSQL, установите зависимости фронтенда и задайте `DATABASE_URL` и `JWT_SECRET`, как описано в инструкции бэкенда. `Ctrl+C` останавливает оба сервера.

Фронтенд доступен по адресу `http://localhost:3000`. Адрес API по умолчанию — `http://localhost:8080`; при необходимости задайте `NEXT_PUBLIC_API_URL` перед запуском или сборкой. Значение `ALLOWED_ORIGIN` в бэкенде должно совпадать с адресом фронтенда. Для запросов с браузера используется `credentials: 'include'`.

После регистрации или входа access JWT хранится только в памяти вкладки. Refresh-токен находится в HttpOnly cookie, которую устанавливает API. При перезагрузке страницы приложение обновляет access JWT через cookie и получает профиль через `/api/v1/users/me`. Выход отзывает refresh-сессию на сервере и очищает локальное состояние.

Выпадающее меню профиля ведёт на `/profile`, где можно просмотреть данные аккаунта и изменить отображаемое имя. Имя сохраняется через `PATCH /api/v1/users/me`.
